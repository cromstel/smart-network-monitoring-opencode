## Method

- Each sample forces two full GCs first, so the reading is retained memory rather
  than uncollected garbage. Without `--expose-gc` this cannot run as designed and the
  script refuses to claim a pass — see the GC row above.
- Growth is a least-squares fit over the whole run, not a start-versus-end delta: a
  sawtooth that returns to baseline is not a leak, and a slow ramp is.
- `unhandledRejection` and `uncaughtException` handlers are installed by the harness.
  Test runners and CI both swallow these, which is why the criterion needs its own trap.
- Event-bus subscribers are attached and detached each cycle, so a listener leak would
  surface as heap growth rather than being hidden by a fresh process.

### The gates have been observed failing

A detector that has never rejected anything is indistinguishable from one that
cannot reject. Each gate below was verified by fault injection, not by inspection:

| Gate | Fault | Observed |
|---|---|---|
| Unhandled rejection | `SOAK_FAULT=rejection` | 12 rejections caught, exit 1 |
| Retained heap | `SOAK_FAULT=memory` | 10.1% retained vs a 5% budget, exit 1 |
| Heap drift | `SOAK_FAULT=memory` | 27.6 MiB drift over 3 min; correctly **not judged** below the 30-minute minimum rather than reporting a false hourly rate |

Re-run any of them with `SOAK_FAULT=<fault> npm run soak`. A run with a fault injected
records it in the Configuration table, so a self-test can never be mistaken for a
genuine pass.
